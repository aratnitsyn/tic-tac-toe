## Purpose

Описывает конечный автомат одной классической партии PvP с очередностью ходов, паузой и однозначным завершением.

**Состояния:** `X_TURN`, `O_TURN`, `PAUSED`, `FINISHED`. Начальное — `X_TURN` после предстартового отсчёта. Конечное — `FINISHED`. До начала партии действуют состояния матча; отдельного ожидания в автомате игры нет.

```text
START --> X_TURN --> O_TURN
             ^         |
             +---------+
             |         |
             v         v
                PAUSED
                   |
                   +--> saved X_TURN / O_TURN

X_TURN / O_TURN --> FINISHED
PAUSED         --> FINISHED
```

Стрелки между X_TURN и O_TURN означают допустимый незавершающий ход; переход к PAUSED означает обнаружение отключения.

| Откуда | Событие / условие | Куда | Эффект |
|---|---|---|---|
| Начало партии | Случайно назначены X/O | X_TURN | Пустое поле 3×3, срок хода +5 секунд |
| X_TURN | Допустимый ход, победы и заполнения поля нет | O_TURN | Зафиксировать ход, новый срок +5 секунд |
| O_TURN | Допустимый ход, победы и заполнения поля нет | X_TURN | Зафиксировать ход, новый срок +5 секунд |
| X_TURN / O_TURN | Победная линия | FINISHED | Победа ходившего |
| X_TURN / O_TURN | Поле заполнено без победной линии | FINISHED | Игровая ничья |
| X_TURN / O_TURN | Истёк срок хода | FINISHED | Поражение текущего игрока |
| X_TURN / O_TURN | Обнаружено отключение | PAUSED | Сохранить очередь и остаток хода |
| PAUSED | Оба подключены до исчерпания запасов | Сохранённое X_TURN / O_TURN | Продолжить оставшееся время хода |
| PAUSED | Запас одного исчерпан раньше | FINISHED | Его поражение |
| PAUSED | Запасы обоих исчерпаны одновременно | FINISHED | Без победителя, не игровая ничья |
| X_TURN / O_TURN / PAUSED | Явный выход из аккаунта | FINISHED | Сдача и завершение сессии |
| X_TURN / O_TURN / PAUSED | Участник сдался | FINISHED | Поражение сдавшегося |

Пауза имеет независимое измерение состава отключённых участников:

```text
A_DISCONNECTED <--> BOTH_DISCONNECTED <--> B_DISCONNECTED
       |                                        |
       +------------> BOTH_CONNECTED <----------+
                            |
                            v
                      resume saved turn
```

BOTH_CONNECTED — условие выхода из PAUSED. Запас каждого отсутствующего игрока расходуется независимо; запас подключённого не расходуется. При повторных отключениях используются остатки общего запаса 30 секунд на игрока за партию. При смене отключённого участника переход выполняется по соответствующим событиям соединения, не сбрасывая запасы.

Результат хранится отдельно от FINISHED:

| Причина | Результат |
|---|---|
| WINNING_LINE | Победа собравшего линию и поражение соперника |
| BOARD_FULL | Игровая ничья |
| TURN_TIMEOUT | Поражение текущего игрока |
| SURRENDER | Поражение сдавшегося |
| DISCONNECT_TIMEOUT | Поражение исчерпавшего запас |
| BOTH_DISCONNECTED_TIMEOUT | Без победителя, отдельно от игровой ничьей |

WINNING_LINE и BOARD_FULL — имена причин для явного описания автомата; формат внешнего API будет определён при проектировании контрактов.

## ADDED Requirements

### Requirement: Alternating turn state machine
Система SHALL начинать партию в X_TURN, случайно назначать символы и менять X_TURN на O_TURN и обратно только после допустимого незавершающего хода. Каждому новому ходу предоставляются 5 секунд. Таблица автомата определяет согласованные переходы партии.

#### Scenario: First move
- **WHEN** X выполняет допустимый ход без победной линии
- **THEN** поле изменяется, игра переходит в O_TURN с новым сроком 5 секунд

### Requirement: Pause retains turn context
При переходе в PAUSED система SHALL сохранять очередь хода и остаток его времени. Ходы запрещены до восстановления обоих игроков; возобновление возвращает игру к сохранённому состоянию, не предоставляя новые 5 секунд.

#### Scenario: Resume O turn
- **WHEN** O_TURN приостановлен с остатком 2 секунды и затем оба восстановились вовремя
- **THEN** игра возвращается в O_TURN с оставшимися 2 секундами

### Requirement: Independent recovery substates
В PAUSED система SHALL различать отсутствие A, B или обоих. Каждый расходует только свой оставшийся запас восстановления. Возврат одного при отсутствующем втором не возобновляет игру и не пополняет запасы.

#### Scenario: One of two returns
- **WHEN** из BOTH_DISCONNECTED восстановился A, но B ещё отсутствует
- **THEN** игра остаётся PAUSED в B_DISCONNECTED, запас A перестаёт расходоваться, запас B продолжает расходоваться

### Requirement: Final game transitions
Система SHALL переводить игру в FINISHED по причинам из таблицы результатов. Победная линия имеет приоритет над заполнением поля в одном ходе. При исчерпании запасов обоих без победителя исход отличается от игровой ничьей. Завершение переводит матч в FINISHED, а обоих игроков — в MENU.

#### Scenario: Last cell wins
- **WHEN** последний свободный квадрат занят ходом с победной линией
- **THEN** игра завершается победой ходившего, а не ничьей

#### Scenario: Recovery deadlines equal
- **WHEN** у обоих отсутствующих игроков запасы заканчиваются в один серверный срок
- **THEN** игра завершается без победителя с причиной BOTH_DISCONNECTED_TIMEOUT

#### Scenario: Surrender during pause
- **WHEN** участник отправляет допустимую команду сдачи в PAUSED
- **THEN** игра завершается его поражением с причиной SURRENDER

### Requirement: Terminal and rejected transitions
FINISHED SHALL быть терминальным. Повторы, недопустимые ходы и устаревшие события не изменяют результат; конфликтующие команды одной версии не создают два перехода. Серверный срок определяет допустимость хода независимо от клиентского таймера.

#### Scenario: Late move
- **WHEN** ход поступает после окончательного завершения по TURN_TIMEOUT
- **THEN** состояние FINISHED и результат остаются неизменными

#### Scenario: Move during pause
- **WHEN** участник пытается сделать ход в PAUSED
- **THEN** ход отклоняется без изменения поля, очереди и сохранённого остатка времени

### Requirement: Logout and deadline transitions
Система SHALL обрабатывать выход из аккаунта в X_TURN, O_TURN или PAUSED как сдачу с переходом в FINISHED, если партия ещё не завершена. Ход или восстановление ровно в соответствующий дедлайн считаются опоздавшими.

#### Scenario: Logout in active game
- **WHEN** текущий участник явно выходит из аккаунта до завершения партии
- **THEN** партия переходит в FINISHED с его поражением по SURRENDER
