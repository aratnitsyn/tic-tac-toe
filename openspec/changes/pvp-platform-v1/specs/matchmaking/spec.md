## Purpose

Обеспечивает автоматический подбор соперников в порядке очереди без рейтингового разделения игроков.

## ADDED Requirements

### Requirement: FIFO pair selection
Система SHALL образовывать пару из двух первых доступных игроков по серверному порядку входа в очередь. Игрок SHALL присутствовать в очереди не более одного раза. Рейтинг и выбор лимита хода не участвуют в подборе первой версии.

#### Scenario: Ordered matching
- **WHEN** A, B и C последовательно входят в очередь и доступны для подбора
- **THEN** первой образуется пара A и B, а C остаётся ждать

#### Scenario: Concurrent matchmakers
- **WHEN** несколько обработчиков пытаются подобрать одних и тех же игроков
- **THEN** каждый игрок включается не более чем в одну незавершённую подготовку матча

### Requirement: Reserve selected players
Система SHALL исключать выбранную пару из доступного подбора на время проверки готовности и предстартового отсчёта, сохраняя исходный приоритет для возможного автоматического возврата.

#### Scenario: Pair awaits acceptance
- **WHEN** для пары запущен таймер готовности
- **THEN** ни один из участников не может быть подобран третьему игроку

### Requirement: Preserve priority on automatic return
Система SHALL сохранять исходный FIFO-приоритет подтвердившего игрока при неподтверждении соперника и подключённого игрока при отключении соперника во время предстартового отсчёта. Вернувшийся игрок не вытесняет уже сформированные пары.

#### Scenario: Earlier player returns
- **WHEN** A вошёл раньше C, готовность пары A/B отменена из-за B, а C ещё доступен
- **THEN** A возвращается с приоритетом выше C

### Requirement: Readiness timeout routing
Система SHALL возвращать не подтвердившего за 10 секунд игрока в меню; подтвердившего — в очередь с сохранённым приоритетом. Если не подтвердил никто, оба возвращаются в меню.

#### Scenario: Neither player accepts
- **WHEN** срок готовности истёк без подтверждений
- **THEN** подготовка отменяется, оба игрока переводятся в меню

### Requirement: Explicit queue cancellation
Система SHALL позволять игроку отменить поиск и перейти из QUEUED в MENU. Отмена и формирование пары SHALL согласовываться без двойного участия: если пара уже закреплена, отмена поиска не должна освобождать участника действующего матча.

#### Scenario: Cancel waiting search
- **WHEN** игрок отменяет поиск до закрепления пары
- **THEN** его запись становится недоступна для подбора, а участие переходит в MENU
